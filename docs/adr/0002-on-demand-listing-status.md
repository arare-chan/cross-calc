# ADR 0002: 東証の上場状態を利用時に更新する

採用日: 2026-10-11

## 背景

市場区分と計画入り・監理・整理銘柄は変動する。利用者には1日1回程度の更新が必要だが、利用されていない間の定期実行は不要である。

## 決定

同一オリジンの `/api/listing-status` で東証公式資料を取得する。ブラウザは銘柄コード入力、銘柄名検索、保存済み銘柄の再表示を契機に取得し、以後は確認時刻から24時間再利用する。開いたままの表示中の画面は1時間ごとと画面復帰時にも期限を確認する。未使用・非表示の画面で定期取得は行わない。

サーバーはインスタンス内キャッシュとCloudflare Cache APIを使う。キャッシュは地域別であり、全世界で厳密に1日1回ではない。キャッシュ退避で再取得が発生する場合もある。スケジューラーや永続DBの追加は不要とする。Cache APIの保存期間は7日、鮮度判定は24時間。失敗した更新は15分後のリクエストから再試行する。

市場区分は月末上場銘柄一覧を基準に、新規上場・市場変更・上場廃止一覧の発効済み行で補正する。計画入りは改善期間一覧と監理一覧の超過計画開示会社、監理・整理は履歴ではなく現在の指定状況を参照する。資料リンクは東証の案内ページから毎回解決する。Excelの公表日・月末基準日と、実際に取得した確認日時を区別して画面に表示する。

Excel読取にはSheetJS公式配布版0.20.3を固定し、サーバー側だけで利用する。公開npmレジストリの古い版は使わない。資料は固定の東証HTTPS URLおよび同ドメインの検証済みExcelリンクに限り、リダイレクトは追跡しない。

## 失敗時と検証

取得や形式検証の失敗時は新しい空の一覧を作らない。前回の情報があれば元の確認日時を保ち、「更新できず・前回の情報」と表示する。前回値もなければ取得失敗を表示する。古い情報は公式情報へのリンクで補う。

パーサー、発効日、同時リクエスト、24時間期限、通信失敗と再試行、ブラウザのキャッシュと銘柄切替をテストする。公開前にCloudflare互換ランタイムと公開APIで実データを確認する。
